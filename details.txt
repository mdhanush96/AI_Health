1. PROJECT OVERVIEW
================================================================================

MedAI is an AI-powered medical assistant that predicts diseases from
natural-language symptom descriptions. It combines a fine-tuned ClinicalBERT
classifier with a hybrid Retrieval-Augmented Generation (RAG) pipeline to
deliver structured, evidence-grounded medical explanations.

Core capabilities:
  - Symptom-based disease prediction (top-3 with confidence scores)
  - Medical report summarization (PDF / TXT / image via OCR)
  - Emergency keyword detection with helpline routing
  - Risk classification (High / Moderate / Low probability tiers)
  - Conversational greeting & small-talk detection
  - Multi-conversation chat UI with persistent history
  - User authentication, profile management, and prediction audit trail

5. ML PIPELINE — PREDICTION FLOW
================================================================================

User Input (symptoms / report file)
        │
        ▼
┌─────────────────────────┐
│  Greeting Detection     │  Regex-based; returns friendly text if matched
│  (non-medical filter)   │
└────────┬────────────────┘
         │ (medical input)
         ▼
┌─────────────────────────┐
│  File Processing        │  PDF → pdfplumber/PyPDF2
│  (if file attached)     │  Image → EasyOCR/pytesseract
└────────┬────────────────┘  Text  → UTF-8 decode
         │
         ▼
┌─────────────────────────┐
│  Emergency Detection    │  Keyword scan (chest pain, seizure, etc.)
│                         │  → flags is_emergency + helpline numbers
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  ClinicalBERT           │  Fine-tuned sequence classifier
│  Classification         │  → top-3 diseases + softmax confidence
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  Symptom Verification   │  Compares user symptoms vs knowledge base
│  (Re-ranking Layer)     │  Word overlap + phrase match + synonyms
│                         │  Score = 60% model + 40% symptom match
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  RAG Pipeline           │
│  ├─ KB Lookup           │  Direct JSON knowledge base query
│  ├─ FAISS Retrieval     │  MiniLM embedding → vector search
│  └─ FLAN-T5 Generation  │  Chunk-based structured explanation
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  Response Assembly      │  Risk classification + emergency flags
│                         │  + RAG explanation + disclaimers
└─────────────────────────┘

8. AUTHENTICATION FLOW
================================================================================

Registration:
  POST /api/auth/register/  { username, email, password }
    → Creates User + UserProfile + Token
    → Returns { token, user: { id, username, email } }

Login:
  POST /api/auth/login/  { username, password }
    → Authenticates credentials
    → Returns { token, user: { id, username, email } }

Session Management:
  - Token stored in localStorage (key: medai_token)
  - Axios interceptor attaches "Authorization: Token <key>" header
  - Protected routes wrapped in <RequireAuth> component
  - Public-only routes wrapped in <PublicOnly> component

Logout:
  POST /api/auth/logout/  (requires Token header)
    → Deletes server-side token
    → Clears localStorage (token + user data)

Tier 1 — disease_info.json (compact reference)
  Per disease: { description, common_symptoms[], advice }

Tier 2 — Per-disease JSON files (knowledge_base/*.json)

                 When to See a Doctor, Preventions }

Diseases Covered:
  Allergy, Arthritis, Bronchial Asthma, Cervical Spondylosis,
  Chicken Pox, Common Cold, Dengue, Diabetes, Drug Reaction,
  Fungal Infection, GERD, Hypertension, Impetigo, Jaundice,
  Malaria, Migraine, Peptic Ulcer Disease, Pneumonia, Psoriasis,
  Typhoid, Urinary Tract Infection, Varicose Veins

FAISS Vector Index:
  - Pre-built from knowledge base chunks
  - Stored as faiss_index.bin + metadata.pkl
  - Queried via MiniLM-L6-v2 sentence embeddings

10. DESIGN PATTERNS & ARCHITECTURE DECISIONS
================================================================================

Pattern                     | Implementation
----------------------------|-----------------------------------------------
Singleton Model Loading     | Thread-safe double-check locking for all ML
                            | models. Loaded once per process, shared across
                            | requests. Prevents redundant GPU memory alloc.
                            |
Config-Driven Architecture  | Central config.py with ~30 env-var overrides
                            | (MEDAI_DEVICE, MEDAI_MODEL_PRECISION, etc.)
                            |
Graceful Degradation        | Fallback chains at every layer:
                            |   pdfplumber → PyPDF2
                            |   EasyOCR → pytesseract
                            |   GPU → CPU
                            |   RAG fails → classification-only
                            |
In-Memory Response Cache    | SHA256-keyed LRU cache for RAG responses
                            | TTL: 300s, max 200 entries, thread-safe
                            |
Two-Pass Verification       | ClinicalBERT predictions re-ranked by
                            | symptom verification (KB matching + synonyms)
                            | Score = 60% model + 40% symptom match
                            |
Conversational UX           | Greeting/small-talk detection prevents ML
                            | pipeline from running on non-medical inputs.
                            | Medical keyword detection overrides greetings.
                            |
Inline CSS                  | Frontend uses entirely inline React styles
                            | (no CSS files or framework). CSS keyframes
                            | injected programmatically.
                            |
localStorage Persistence    | Conversations, auth tokens, and user info
                            | stored client-side in localStorage
                            |
Half-Precision Support      | Optional float16 model casting via
                            | MEDAI_MODEL_PRECISION env var for lower VRAM

12. SETUP & RUN
================================================================================

Backend:
  cd health_ai_project/backend
  pip install -r requirements.txt
  python -m spacy download en_core_sci_md
  python manage.py migrate
  python manage.py runserver

Frontend:
  cd health_ai_project/frontend
  npm install
  npm start

Environment Variables (optional):
  MEDAI_DEVICE             = cpu | cuda           (default: auto-detect)
  MEDAI_MODEL_PRECISION    = float32 | float16    (default: float32)
  MEDAI_CACHE_TTL          = <seconds>            (default: 300)
  MEDAI_CACHE_MAX_SIZE     = <count>              (default: 200)
  MEDAI_FAISS_TOP_K        = <count>              (default: 5)
