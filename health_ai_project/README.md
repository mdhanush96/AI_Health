## Architecture

```
User (Browser)
     ↓
React Frontend (port 3000)
     ↓
Django REST API (port 8000)
     ↓
ClinicalBERT ML Engine (GPU/CPU)
     ↓
Disease Knowledge Base (JSON) + MySQL Database (Prediction Logs)
```

---

## Features

- **ClinicalBERT Disease Prediction** – Top 3 predictions with confidence scores
- **GPU Acceleration** – Automatic CUDA detection (RTX 2050 optimized), CPU fallback
- **Risk Classification** – High / Moderate / Low probability tiers
- **Emergency Detection** – Flags critical symptoms (chest pain, breathing difficulty, etc.)
- **Prediction Logging** – Full audit trail in database
- **Prediction History** – View past predictions in the frontend
- **Medical Disclaimer** – Responsible AI safety layer
- **Admin Panel** – Django admin for prediction log management

## Quick Start (Windows)

### Prerequisites

- Python 3.11+
- Node.js 18+
- MySQL 8.x (required)
- NVIDIA GPU drivers + CUDA toolkit (optional for GPU)

### 1. Backend Setup

```powershell
cd backend

# Create virtual environment
python -m venv ..\.venv
..\.venv\Scripts\Activate.ps1

# Install dependencies
pip install -r requirements.txt

# Run migrations
python manage.py migrate

# Create superuser (optional)
python manage.py createsuperuser

# Start server
python manage.py runserver
```

### 2. Frontend Setup

```powershell
cd frontend

# Install dependencies
npm install

# Start dev server
npm start
```

### 3. Access

| Service | URL |
|---|---|
| Frontend | http://localhost:3000 |
| Backend API | http://127.0.0.1:8000 |
| Admin Panel | http://127.0.0.1:8000/admin |
| Health Check | http://127.0.0.1:8000/api/health/ |

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/predict/` | Submit symptoms for disease prediction |
| `GET` | `/api/health/` | API health check + GPU status |
| `GET` | `/api/history/` | Recent prediction history |

### Example Request

```json
POST /api/predict/
{
  "symptoms": "I have severe headache and nausea"
}
```

### Example Response

```json
{

      "disease": "migraine",
      "confidence": 72.45,

      }
    }
  ],
  "emergency": null,
  "disclaimer": "This prediction is generated by an AI model and is NOT a medical diagnosis."
}
```

## MySQL Database Setup (Required)

MedAI uses **MySQL** as its primary database. Follow these steps to set it up:

### Step 1: Install MySQL

- Download and install [MySQL Community Server 8.x](https://dev.mysql.com/downloads/mysql/)
- During installation, set a root password (remember it!)
- Ensure the MySQL service is running

### Step 2: Create the Database and User

Open **MySQL Shell** or **MySQL Workbench** and run:

```sql
-- Create the database
CREATE DATABASE medai_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- (Optional) Create a dedicated user instead of using root
CREATE USER 'medai_user'@'localhost' IDENTIFIED BY 'your_secure_password';

-- Grant privileges
GRANT ALL PRIVILEGES ON medai_db.* TO 'medai_user'@'localhost';
FLUSH PRIVILEGES;
```

### Step 3: Configure Environment Variables

Set these environment variables (or they default to the values shown):

```
MYSQL_DATABASE=medai_db
MYSQL_USER=root
MYSQL_PASSWORD=yourpassword
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
```

On **Windows PowerShell** (current session):

```powershell
$env:MYSQL_DATABASE = "medai_db"
$env:MYSQL_USER = "root"
$env:MYSQL_PASSWORD = "yourpassword"
$env:MYSQL_HOST = "127.0.0.1"
$env:MYSQL_PORT = "3306"
```

### Step 4: Run Migrations

```powershell
cd backend
python manage.py migrate
```

This will auto-create the following tables in `medai_db`:

| Table | Description |
|---|---|
| `api_userprofile` | User health profiles (phone, DOB, gender, blood group, height, weight, allergies, etc.) |
| `api_predictionlog` | Prediction audit trail (symptoms, disease, confidence, risk level, emergency flag) |
| `authtoken_token` | DRF auth tokens |
| `auth_user` | Django built-in user accounts |
| `auth_group` | Django groups |
| `auth_permission` | Django permissions |
| `django_*` | Django internal tables (admin log, content types, sessions, migrations) |

### Database Schema (Key Tables)

```
api_userprofile
├── id              (BIGINT, PK, AUTO_INCREMENT)
├── user_id         (INT, FK → auth_user.id, UNIQUE)
├── phone           (VARCHAR(15))
├── date_of_birth   (DATE, NULLABLE)
├── gender          (VARCHAR(20))  — male / female / other / prefer_not_to_say
├── blood_group     (VARCHAR(10))  — A+ / A- / B+ / B- / AB+ / AB- / O+ / O- / unknown
├── height_cm       (DOUBLE, NULLABLE)
├── weight_kg       (DOUBLE, NULLABLE)
├── allergies       (LONGTEXT)
├── medical_conditions (LONGTEXT)
├── emergency_contact  (VARCHAR(15))
├── address         (LONGTEXT)
├── avatar_initial  (VARCHAR(2))
├── created_at      (DATETIME)
└── updated_at      (DATETIME)

api_predictionlog
├── id              (BIGINT, PK, AUTO_INCREMENT)
├── symptoms        (LONGTEXT)
├── predicted_disease (VARCHAR(255))
├── confidence      (DOUBLE)
├── risk_level      (VARCHAR(50))
├── is_emergency    (BOOL)
└── created_at      (DATETIME, INDEXED)

auth_user
├── id              (INT, PK, AUTO_INCREMENT)
├── username        (VARCHAR(150), UNIQUE)
├── email           (VARCHAR(254))
├── password        (VARCHAR(128))  — hashed
├── first_name      (VARCHAR(150))
├── last_name       (VARCHAR(150))
├── is_active       (BOOL)
├── is_staff        (BOOL)
├── is_superuser    (BOOL)
├── date_joined     (DATETIME)
└── last_login      (DATETIME, NULLABLE)
```
